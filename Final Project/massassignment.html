SECURITY LAB

Mass Assignment Vulnerability

Understand the vulnerability. Simulate the attack. Apply the fix.

00

About the Vulnerability

Mass Assignment occurs when an application automatically assigns user input to object properties without checking which fields are allowed. An attacker can send unauthorized properties such as role or isAdmin. This may allow the attacker to gain administrator privileges.

OWASP CWE-915
01

Source Code

Compare the vulnerable code with the secure solution.

Vulnerable Code

Vulnerable code

The application accepts all properties sent by the user. 

1  const user = {
2      username: "sally",
3      email: "sally@gmail.com",
4      role: "user",
5      isAdmin: false
6  };
7
8  function updateUser(requestBody) {
9     function Object.assign(user, requestBody) {
    for (let key in requestBody) {
        user[key] = requestBody[key];
    }

}
10     return user;
11 }

Vulnerability Found — Line 9

The problem is in line 9. Object.assign() copies all properties from the request into the user object without checking them. An attacker can change role and isAdmin to gain administrator privileges.

Fix Code

Fixed code

The application only accepts approved properties. 

1  const user = {
2      username: "sally",
3      email: "sally@gmail.com",
4      role: "user",
5      isAdmin: false
6  };
7
8  function updateUser(requestBody) {
9      const allowedFields = [
10         "username",
11         "email"
12     ];
13
14     allowedFields.forEach(field => {
15         if (requestBody[field] !== undefined) {
16             user[field] = requestBody[field];
17         }
18     });
19
20     return user;
21 }

Fix Applied — Lines 9–18

We replaced Object.assign() with an Allowlist. Lines 9–12 define the permitted fields: username and email. Lines 14–18 update only approved fields, preventing attackers from changing role or isAdmin.
